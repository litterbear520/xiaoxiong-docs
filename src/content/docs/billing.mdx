小熊API 按用量计费：每次请求按实际处理的 token 数从账户余额扣费，没有月费。本页介绍计费方式、充值方法和消费记录。

## 计费方式

### 按 token 计费

对话模型的价格单位是美元 / 百万 token，分为以下几项：

- **输入** — 你发送的全部内容，包括系统提示、历史对话、图片和工具定义
- **输出** — 模型生成的内容，包括思考过程，通常比输入贵好几倍
- **缓存读取** — 与最近请求开头相同的那部分输入，按更低的价格计费。GPT 模型自动命中；Claude 模型需要在请求中标记缓存内容，详见 [Claude 格式](/docs/claude/)
- **缓存写入** — Claude 模型在模型广场中显示此价格，但实测写入缓存不额外收费，按普通输入价计费

一次请求的费用 = 输入 token × 输入价 + 输出 token × 输出价，命中缓存的部分按缓存读取价计算。

### 价格与余额

- 价格参照厂商官方的美元价格，以 [模型广场](/pricing) 显示的为准。
- 余额以美元计。充值时 1 元人民币得到 10 美元余额，即 ¥1 = $10。

### 图片模型

图片模型同样按 token 计费，文字输入、图片输入和图片输出分别计价。实测 gpt-image 模型每张约 $0.01–0.03（透明背景约 $0.06），`gemini-3.1-flash-image` 每张约 $0.09，详见 [图片生成](/docs/images/)。

### 失败与中断

- 返回错误的请求不扣费，包括被内容审核拒绝的请求。
- 图片请求发出后，即使客户端中途断开或关闭画图页面，图片仍会生成并扣费。不要把客户端超时设得太短。

## 余额与充值

### 注册与登录

打开 [登录页](/sign-in)，选择一种方式：

| 方式 | 说明 |
| --- | --- |
| GitHub | 用 GitHub 账号一键登录 |
| Google | 用 Google 账号一键登录 |
| 邮箱 | 注册时向邮箱发送验证码。只支持常见邮箱：Gmail、QQ、Foxmail、163、126、Outlook、Hotmail、iCloud、Yahoo |

GitHub 和 Google 登录只能从主线路 `https://api.little-bear.app` 发起，其他线路请用邮箱登录。登录页要先勾选同意隐私政策，第三方登录按钮才能点击。

### 充值

<Steps>

1. **打开钱包**

   在控制台打开 [钱包](/wallet)，点击 **充值**。

2. **选择金额和支付方式**

   选择一个金额，或输入 1 到 10000 之间的整数（单位：元），再选择支付宝或微信，点击 **去支付**。

3. **扫码付款**

   收银台显示一个二维码和精确到分的金额。用对应的 App 扫码，务必按收银台显示的金额付款，金额不一致时系统无法识别订单。

4. **等待到账**

   通常十几秒内自动到账，钱包页的余额随之更新。

</Steps>

- 收银台的金额可能比你选的少几分钱，用来区分同时进行的订单。到账余额仍按你选的金额计算。
- 二维码 5 分钟内有效，过期后重新下单。
- 付款超过 5 分钟仍未到账，或收银台提示暂时不能付款，请把订单号发给小熊处理。

### 充值赠送

- 单笔充值满 10 元起另有赠送，金额越大送得越多，每档的赠送额标在充值窗口的金额旁。
- 赠送的余额有有效期，扣费时先扣赠送部分。
- 每个账号可以购买一次新人礼包，价格和内容见充值窗口。

### 余额不足

每次请求开始前，系统按输入长度预估费用并冻结这部分余额，请求结束后按实际用量多退少补。

| 报错 | 原因 | 解决办法 |
| --- | --- | --- |
| `403 Insufficient user quota` 或 `用户额度不足` | 账户余额不足 | 充值。重试不会自行恢复 |
| `403 Not enough quota to pre-consume` 或 `预扣费额度失败` | 余额不够冻结这次的预估费用，常见于余额很少而输入很长时 | 充值，或缩短输入（例如开一个新对话） |

### 密钥额度

所有 API 密钥共用账户余额，密钥本身没有余额。在 [API 密钥](/keys) 页可以给密钥设置额度上限和过期时间，限制它最多能花多少：

- 剩余额度不够这次请求时，返回 `403 token quota is not enough`。
- 额度用完或过期后，这个密钥返回 `401 Invalid token`，其他密钥不受影响。

- [概览](/dashboard) — 账户余额和近期用量
- [用量统计](/dashboard/models) — 按时间段汇总消费、请求数和 token，可以按密钥或按模型查看

每次请求的实际扣费以使用日志为准。

## 费用估算

- 用 `gpt-6-luna` 发送 `你好`，大约记 300 个输入 token 和 10 个输出 token：GPT 模型的上游会在每次请求前附带一段固定的系统指令，这部分计入输入。Claude 和 Gemini 模型没有这段指令，同样的请求只记几个输入 token。
- 会思考的模型，思考过程按输出计费。例如 `gemini-3.8-flash` 回答简单问题，也可能先输出一两百个思考 token。
- 小熊API 不提供计算 token 数的接口（`count_tokens` 返回 `404`）。需要估算时，先发一个小请求，再到使用日志查看实际用量。
